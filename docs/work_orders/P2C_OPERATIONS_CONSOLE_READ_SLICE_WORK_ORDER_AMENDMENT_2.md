## 3. `pyproject.toml` — exact authorized edits

`pyproject.toml` may be edited only to:

1. add `jsonschema` and `referencing` to `[project.optional-dependencies]`
   `dev` (or an equivalent dev-only dependency group), resolving F12;
2. implement exactly one of SPEC R23's two deterministic OpenAPI-drift
   policies for packages that affect generated OpenAPI output (at minimum
   FastAPI, Pydantic) — either (a) exact/bounded version constraints on
   every package a probe confirms changes the generated bytes, or (b)
   removal of reliance on any dependency-sensitive full-document hash in
   favor of the environment-independent structural proof already required
   by R21. A floating range paired with a documented version-assumption
   note satisfies neither option and is not acceptable. Whichever policy is
   chosen must retain a testable negative-protection mechanism against
   unrelated API drift. If policy (a) is chosen, the worker must probe and
   name the package(s) that actually change the generated OpenAPI bytes,
   record the exact resolved versions in the evidence, and prove an
   unrelated path/method/schema/security mutation still fails the
   golden-chain test under the pinned versions;
3. record CPython `3.13.12` as the review interpreter (as a comment,
   `classifiers` entry, or documentation reference — not by lowering the
   existing `requires-python = ">=3.12"` floor).

Explicitly prohibited in this file for this amendment:

- generating, modifying or deleting `uv.lock`;
- adopting `uv` or any other new lock-file strategy;
- widening `requires-python` below `3.12` or otherwise loosening the
  existing floor;
- adding any dependency not named in items 1-2 above;
- a floating/unbounded version range for FastAPI or Pydantic combined with
  only a documented-assumption note in place of policy (a) or (b).

## 4. `_shift_queries.py` — exact helper boundary

`_shift_queries.py` is a new authorization under this amendment (Amendment 1
authorized only the event-list query extraction into `_event_queries.py`; it
did not authorize any mutation extraction). `_shift_queries.py` may contain
only:

- shift-query and shift-mutation SQL/materialization code extracted from
  `sql_ledger.py`, restoring the pre-compression formatting F13 identified
  (the docstring and the two unrelated mutation methods);
- the imports strictly required by that extracted code.

It may not:

- change any mutation's observable behavior;
- own queries or mutations for any record type other than shifts;
- become a second Ledger implementation or duplicate `sql_ledger.py`'s
  public surface;
- apply compressed formatting, minification, or line-merging to satisfy the
  300-line guard in either file.

`sql_ledger.py` must delegate to this helper without changing its own public
contract. This follows the same delegation *pattern* as the
`_event_queries.py` split Amendment 1 authorized, without extending
Amendment 1's own authorization to mutation code.

## 5. Canonical schema — exact repair boundary

`packages/workspace-contracts/tasks/task.schema.json` and
`packages/workspace-contracts/customers/customer-request.schema.json` may be
edited only to:

- allow `null` (or an equivalent nullable union) for every field the
  canonical domain model permits to be null, starting with `Task.owner_id`;
- replace each schema's generic `"status": {"type": "string"}` with an
  enum constrained to the canonical `TaskStatus` / `CustomerRequestStatus`
  members;
- add the positive/negative tests required by SPEC R26.

They may not:

- remove or weaken any currently-required field;
- diverge from the canonical Pydantic model's actual accepted value set;
- be forked into a separate open-work-only vocabulary — `open-work.
  schema.json`'s existing `$ref` to these two files must continue to resolve
  unchanged.

## 6. 500/501 ceiling repair (uses only already-authorized test paths)

Findings F16-F18 require behavioral and test repair inside the
already-authorized 25-path ceiling (principally
`apps/workspace-api/src/workspace_api/api/shifts/router.py`,
`apps/workspace-api/src/workspace_api/api/events/router.py`,
`apps/workspace-api/src/workspace_api/infrastructure/repository.py`,
`tests/integration/test_p2c_read_api.py`,
`tests/integration/test_sql_ledger_postgres_live.py`); this amendment adds
no new path for this repair because none is needed. The worker must prove
the exact SPEC R27 matrix — no partial substitute is acceptable on any
backend:

- **InMemoryLedger:** `GET /shifts`, `GET /events`, and each of the
  `tasks`/`customer_requests`/`incidents` open-work groups each admit 500
  records (HTTP 200) and refuse 501 records (controlled HTTP 409/422, no
  partial result). Finding F16 showed 501 shifts returning HTTP 200 with all
  records on this path — a real behavioral gap, not a documentation-only
  defect, and it must be closed here.
- **SQLite:** the identical full matrix above, driven through the real
  API/`SqlLedger` dependency chain.
- **PostgreSQL 16 live:** the identical full matrix above — every one of the
  five surface/group cases, not only one representative overflow — driven
  through the real API/`SqlLedger` dependency chain, with exact
  container/anonymous-volume cleanup (resolving F17; a bare row-count check
  against the database alone does not satisfy this).

The docstring in `test_p2c_read_api.py` claiming a limit/ceiling test exists
must become true for this full matrix or must be corrected (F18).
