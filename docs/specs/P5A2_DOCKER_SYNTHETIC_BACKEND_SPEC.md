## Testable rehearsal requirements

**R1 — isolated lifecycle.** After reviewed WO admission, one wrapper checks Docker/driver/image, creates exactly one uniquely named PostgreSQL 16 container on `127.0.0.1:<dynamic-port>` using a new ephemeral password and no bind/named volume, and records actual image ID/container name/port. The image may be pulled once only if the WO permits it. Use native stable readiness and `apply_migrations_twice` for all current 001–011 SQL migrations. Run only the named P5-A2 opt-in test target using a process-local URL; never log the raw URL/password or read `.env`. Capture container-created identity and anonymous volumes; `finally` removes **only** this run's container/volumes, then verifies their absence. A name collision, failed create, readiness/migration/test error or incomplete cleanup is a nonzero result with sanitized failure class. A failed `docker run` must not trigger deletion of an unrelated container. Receipt reports cleanup outcome accurately, never a still-running backend after successful cleanup.

**R2 — fixed canonical fixture, independent oracle.** Use the unchanged `tests/unit/proactive_helpers.py` recipe `history([4] * 36)`: `scope_id=PUBLIC_SCOPE`, `actor_id=PUBLIC_ACTOR` are fixture-only assertions; `START=2026-01-01T00:00:00Z`; Report `i` is `report(i, 4)`, with cutoff `START+i hours`; query window is `[START, START+36 hours)` and initial `run_as_of=START+36 hours`. Create exactly one parent Shift per Report, with the Report's deterministic `shift_id`, `starts_at=cutoff-1 hour`, `ends_at=cutoff` and fixed aware `created_at=starts_at-1 hour`; no ambient `datetime.now`. Persist through actual `SqlLedger`, dispose connections, then reconstruct a new `SqlLedger`/engine before reading. Persist one additional genuine version-2 successor for shift 0 under R3, giving **36 shifts and 37 persisted Report versions**. The independent **before-BUILD** fixture/analysis oracle is `.venv/p5a2-docker-prebuild-oracle-20261025.json`, SHA-256 `12ad36cbd335a8def5e7ac9a6ade6f0bf542cb45af4cec1760a7291a8f6973c0`, 129413 bytes, fixture ID `P5A2-PUBLIC-PG36-V1`; Root froze it from unchanged accepted helper/pure code before the new SQL loader exists. A later reviewed WO may copy these exact bytes into `tests/fixtures/` and pin that copy. The SQL loader must match this oracle; it must not generate or redefine expected IDs, content hashes, manifests, selected versions, lineage or analysis. Seed no production data or actual operator records. Neither today's `is_current` nor mutable `status` is a historical selection oracle.

**R3 — SQL persistence and chronology.** On reconnect, exact counts/IDs/version/cutoff/created_at/full immutable Report content and manifest/digest match the R2 golden oracle semantically; every top-level persisted cutoff and availability timestamp remains offset-aware. Today's `status`/`is_current` must not drive either selection. Source event times remain bounded by selected cutoff.
